# Приватность, дружба и управление данными

Аккаунт приватный по умолчанию, в том числе старый профиль без поля `visibility`.
Меню аккаунта показывает свой профиль, друзей и профиль, открытый по публичной ссылке.
Публичный режим разрешает просмотр по `index.html?profile=UID` без входа.
Друг видит профиль и коллекции `progress`, `cards`, `tests`; изменять их может владелец или администратор.
Список друзей, приглашения и закрытые профили не входят в публичный каталог.

Кнопка «Создать код дружбы» выдаёт случайный 128-битный одноразовый код на 7 дней.
Ссылка `index.html?friend=CODE` требует входа и явного принятия взаимного доступа.
Принятие атомарно записывает приглашение и обе стороны дружбы. Любой участник может прекратить дружбу;
для публичного профиля это не отменяет публичный доступ. Создатель может отменить неиспользованный код.

## Запуск в рабочем Firebase

GitHub Pages публикует только сайт. Правила Firestore нужно развернуть **отдельно**.
До записи `system/access` интерфейс не разрешает включать публичность или создавать/принимать приглашения.
Эта запись служит маркером развёртывания, а не заменяет правила безопасности.

1. Сохранить текущую базу/правила в непубличном месте через средства администратора проекта.
2. Установить Node 24, pnpm и Java 21 для локальных проверок; `pnpm install --frozen-lockfile`, затем `pnpm test`.
3. Войти в Firebase CLI под владельцем проекта: `pnpm exec firebase login`.
4. После согласования PR развернуть правила:
   `pnpm exec firebase deploy --only firestore:rules --project english-skill-tree-01`.
5. Привязать управление к **существующему Firebase Auth UID** нужного аккаунта. Не искать по отображаемому имени!
   В Firebase Console → Authentication найти точный адрес входа (`Demid` латиницей даёт `demid@users.skilltree.app`),
   проверить его и скопировать UID. Создать документ `accessAdmins/UID` с полем `name: "Demid"`.
   Запись этой коллекции из приложения запрещена даже администратору.
6. Создать документ `system/access` с числовым полем `version: 1`. Делать это только после шага 4.
7. Опубликовать сайт через согласованный мердж, проверить вход владельца, приглашение, закрытый профиль
   и отказ в управлении для другого участника. При необходимости откатить UI, сохранив ограничивающие правила.

Вместо ручных шагов 5–6 можно использовать `scripts/setup-access.cjs` с Application Default Credentials
владельца Firebase проекта. Скрипт разрешает только уже существующий и включённый Auth-аккаунт с профилем:

```sh
node scripts/setup-access.cjs --project english-skill-tree-01 --nick Demid --confirm-email demid@users.skilltree.app
```

Ключи сервисных аккаунтов, пароли и токены в Git не добавлять. Вход в GitHub сам по себе не даёт прав Firebase.
Если логин кириллицей, нужен его фактический Auth email, который получается по той же схеме `nickToEmail`,
что и раньше; скрипт вычислит адрес и проверит `--confirm-email` до записи.

## Страница управления

`admin.html` — отдельная страница без ссылок из основного интерфейса, с `noindex,nofollow`.
Её адрес не является средством защиты: доступ к каждому чтению/изменению проверяют правила Firestore
по `accessAdmins/{auth.uid}`. Совпадение имени с «Demid» прав не даёт.

Страница показывает все документы данных приложения с загрузкой по 50 записей: профили,
подколлекции грамматики, слов, тестов и друзей, приглашения, общие настройки и состояние доступа.
Можно редактировать JSON существующего документа, просмотреть «было/станет», подтвердить сохранение.
Транзакция отклоняет сохранение, если документ успел измениться после открытия.
Роли администраторов доступны только для просмотра. Пароли Firebase Auth в Firestore не хранятся и здесь не показываются.

Старый публичный экспорт `migration.js` и выбор произвольного старого ученика для импорта удалены.
Сервис-воркер удаляет предыдущий кэш при активации. Это не удаляет старые копии и историю Git:
данные, опубликованные раньше в экспорте, нельзя сделать задним числом секретными. Прогресс в рабочей
базе не удаляется; перед удалением экспорта сохранена локальная копия вне репозитория для частного переноса.

## Проверки

`pnpm test` запускает настоящий Firestore Emulator в проекте `demo-skill-tree`.
Тесты проверяют владельца, старый приватный профиль, друга, постороннего, анонимного посетителя и администратора;
публичность и её отзыв; запрет правок чужих данных и общих настроек; атомарность принятия/отзыва;
истёкшие, отменённые, использованные коды; запрет подделки роли и обхода через неизвестные коллекции.

Для локального браузера запустить `pnpm exec firebase emulators:start --only auth,firestore --project demo-skill-tree`,
поднять статический HTTP сервер и открыть `http://127.0.0.1:PORT/?emulator=1`.
Параметр эмулятора принимается только на loopback; проект переключается на `demo-skill-tree`, рабочая база не используется.
